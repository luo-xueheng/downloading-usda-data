# downloading-usda-data

Download, process, and export seven USDA datasets: WASDE, Export Sales, World Agricultural Production, Grain Trade, Oilseed Trade, Costs and Returns, and RMA Summary of Business. Supports Python DataFrames, streaming CSV, caching, version history, and failure recovery.

## Installation and credentials

Requires Python 3.11+ and macOS/Linux. Run locking uses `fcntl`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install '.[dev]'
.venv/bin/python -m usda_data list-datasets
```

For development, use `.venv/bin/python -m pip install -e '.[dev]'`. Export Sales and the three report datasets use the FAS API; follow [.env.example](.env.example) to set `USDA_FAS_API_KEY` in a local `.env` file or an environment variable with the same name. See [Credential setup](docs/credential_setup.md).

## Download data

The following command downloads one complete WASDE release:

```bash
.venv/bin/python -m usda_data fetch --dataset wasde --start 2026-11-10 --end 2026-11-10 --data-dir data --output-dir data/exports
```

The final file locations are specified in `data/exports/wasde.latest.json`. The CSV preserves field codes, nulls, exact decimals, provenance, and snapshot information.

```python
import json
from pathlib import Path
from usda_data.schema import Schema

root = Path("data/exports")
selected = json.loads((root / "wasde.latest.json").read_text())
schema = Schema.load(root / selected["schema_path"])
for chunk in schema.read_csv_chunks(root / selected["csv_path"], chunk_size=1000):
    print(chunk.head())
    break
```

## Batch downloads, updates, and exports

```bash
.venv/bin/python -m usda_data fetch --dataset all --config config/small_sync.json --dry-run
.venv/bin/python -m usda_data sync --config config/small_sync.json
.venv/bin/python scripts/aggregate_exports.py --input-dir data/exports
.venv/bin/python -m usda_data validate --input-dir data/exports/datasets
```

The small configuration demonstrates only the specified scope. The historical full-backfill configuration, `config/full_backfill.json`, was frozen on 2026-11-16 and does not automatically represent all data available today. For task discovery, downloads, and aggregation over a new scope, see [Batch downloads](docs/backfill.md). See [Updates and recovery](docs/updates_and_recovery.md) for update and recovery strategies, and [SQL transfer](docs/sql_transfer.md) for database imports.

## Tests

```bash
.venv/bin/python -m pytest
```

By default, this runs offline functional, dataset, and regression tests. Test inputs are centralized in `test/fixtures/`, and test outputs go to system temporary directories; the old `data/` directory and acceptance logs are not required. See [test/README.md](test/README.md) for separate instructions on live, performance, historical acceptance, and seven-interface replay checks.

## Repository structure

- `src/usda_data/`: Downloading, parsing, storage, synchronization, CSV/SQL processing, and required metadata.
- `scripts/`: General acquisition, task planning, aggregation, example generation, and SQL tools.
- `config/`: Runtime configuration and schema migration rules.
- `schemas/`: Field definitions for current interfaces and aggregate outputs.
- `test/`: Test code, test tools, independent reference values, and fixed source fixtures.
- `examples/`: One CSV excerpt per primary dataset, commands, and a provenance index.
- `docs/`: Usage guides, field dictionaries, source limitations, and retained historical documents.

`data/` contains local caches and outputs generated at runtime and is not committed to Git. The complete data and acceptance records from before the 2026-11-17 cleanup were moved to an archive next to the repository; the [migration guide](docs/repository_cleanup.md) records its location, recovery steps, and file mappings. All existing Markdown documents have been retained; see the [historical version](docs/history/README.before-cleanup.md) for the original README.
