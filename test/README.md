# Running tests and using fixtures

All test code, test tools, and fixed inputs are centralized in this directory. After installing development dependencies, run from the repository root:

```bash
.venv/bin/python -m pytest
```

By default, `live` and `historical` are excluded, while foundation, dataset, synchronization, interface, and historical-layout regression tests run. Offline tests block real socket connections and write outputs to pytest temporary directories; they do not depend on the historical archive next to the repository or on complete downloaded data.

## Directories

| Directory | Purpose |
|---|---|
| `unit/` | HTTP, storage, security, field precision, and independent evidence verification |
| `datasets/` | WASDE, ERS, ESR, PSD, reports, and RMA; includes explicitly marked live tests |
| `integration/` | Synchronization, CLI, SQL, example data, and aggregate publication |
| `regression/` | Previously identified historical PDF layouts, missing announcements, and concurrent recovery issues |
| `live/` | Real-request verification of historical source catalogs and alternative attachments |
| `historical/` | Rechecks of previous complete delivery records; excluded from current default regression tests |
| `performance/` | Memory checks and diagnostic scripts for large requests |
| `tools/` | Test-fixture acquisition, seven-interface consistency checks, and initial independent evidence verification |
| `fixtures/` | Fixed official source bytes, acquisition receipts, independent reference values, and test-only configuration |

`fixtures/phase_*` retains the original fixture groupings to avoid reselecting samples or confusing independent reference values with development samples. The one-CSV-per-dataset rule applies to `examples/` and does not limit fixture coverage of historical formats and exceptional cases.

## Live verification

```bash
.venv/bin/python -m pytest -m live
```

FAS tests require `USDA_FAS_API_KEY`. Live sources may be revised or temporarily unavailable; failed or skipped tests do not count as passes. Live verification was not rerun during this repository cleanup.

## Full-output consistency across seven interfaces

```bash
.venv/bin/python test/tools/verify_examples.py --output-dir .cache/interface-check
```

This builds an independent cache from fixed official fixtures and compares the complete Python and CLI outputs for each dataset with networking disabled. It generates substantial temporary caches and full exports in the ignored `.cache/` directory, unlike the committed 200-row examples. Use a fresh output directory when verifying again to avoid reusing caches generated by older tools.

## Historical delivery rechecks

```bash
USDA_ARCHIVE_ROOT="../downloading-usda-data-archive-20261117/original" .venv/bin/python -m pytest test/historical -m historical
```

These tests read the complete data, original code snapshots, and acceptance records in the external archive. The archive is not included in a Git clone and must be retained separately or restored. Some example directories referenced by older tests, including `artifacts/acceptance/phase-10/examples/` and `artifacts/acceptance/phase-05/sample/exports/`, were already missing before the cleanup, so historical delivery rechecks are not guaranteed to pass in full; the cleanup did not fabricate or backfill historical pass records.

## Performance checks

```bash
.venv/bin/python test/performance/verify_full_export_memory.py --data-dir /path/to/full-data --output .cache/performance/full_export_memory.json
.venv/bin/python test/performance/profile_report_memory.py --data-dir /path/to/full-data --config config/full_backfill.json --task world-production-full
```

These two checks replay large requests, require complete source caches and the corresponding task state, and may update cache state; running them on a working copy is recommended. Full historical performance tests were not rerun during this cleanup.
